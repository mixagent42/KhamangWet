## 1. Visual Pillars

1. **ขลังแต่อ่านออก (Atmosphere without obscurity)** แสง หมอก และเงาสร้างมิติ แต่ตัวละคร ศัตรู และ telegraph ต้องเห็นชัดเสมอ (GDD §3 pillar 2; Art Lock §2)
2. **ฉากลึก ตัวละครคม (HD-2D depth)** ฉาก 3D มีชั้นความลึกด้วยแสง หมอก และการเบลอเฉพาะฉากหน้าและฉากหลัง ส่วนตัวละคร 2D คมชัดและติดพื้นอย่างมีน้ำหนัก
3. **ไทยแบบเคารพและตีความใหม่ (Respectful reinterpretation)** ได้แรงบันดาลใจจากสถาปัตยกรรม วัสดุ และความเชื่อไทย แต่เป็นงานแต่งขึ้นใหม่ ไม่ใช่การสอนหรือคัดลอกพิธีกรรมจริง (GDD L13, L89)
4. **สม่ำเสมอเมื่อขยายขนาด (Consistency at MMO scale)** ทุก asset ใช้สัดส่วน มุมกล้อง palette และมาตรฐานเดียวกัน เพื่อให้ผู้เล่นหลายสิบคนบนจอยังดูเป็นโลกเดียวกัน
5. **อาคมมีจังหวะ (Readable sorcery)** ทุกสกิลมีช่วงเริ่ม จุดปะทะ และการสลายที่อ่านได้ ความเข้มของ VFX ไม่บังการต่อสู้ (Art Lock §4)

### 3.2 วัสดุ [LOCK]+[R]
ไม้เก่า หิน ตะไคร่ ผ้า เครื่องราง กระดาษยันต์ โลหะที่ผ่านกาลเวลา (ทองเหลือง ทองหม่น สนิม) **[R] กฎ:**
- รายละเอียดผิววัสดุต้องอยู่ในความถี่ที่อ่านได้ที่ default zoom และห้ามมี noise ละเอียดจนดูเหมือนภาพสั่นตอนกล้องเลื่อน
- texel density สม่ำเสมอทั้ง zone (ค่าใน `ASSET_PIPELINE.md §4`)
- พื้นที่เดินได้ต้องอ่านต่างจากพื้นที่เดินไม่ได้ ทั้งด้วยวัสดุ ค่าสว่าง และขอบ ไม่ใช้สีอย่างเดียว

### 3.3 แสง หมอก และเงา
- **แหล่งแสง [LOCK]:** โคม เทียน กองไฟ และแสงเหนือธรรมชาติ
- **[R] โครงสร้างค่าสว่าง 3 ระนาบ:**
  1. **ฉากหน้า (foreground):** มืดเป็นเงาตัด เบลอได้ (tilt-shift) **ห้ามบังวงต่อสู้**
  2. **ระนาบเล่นเกม (gameplay plane):** ต้องมี**แสงขั้นต่ำ (lighting floor)** เพื่อให้ตัวละครและศัตรูอ่านได้แม้ในฉากมืด
  3. **ฉากหลัง:** จางลงด้วยหมอก ค่าความต่างต่ำ
- **[R] Hero light:** ตัวละครผู้เล่นมีแสงอ่อนติดตัวหรือ rim light เพื่อรักษาความอ่านง่าย (วิธีทำอยู่ใน `VISUAL_PROTOTYPE_PLAN.md §2.2`)
- **[R] หมอก:** ความหนาแน่นในระยะของ gameplay plane มีเพดาน หมอกหนาใช้ได้เฉพาะฉากหลังหรือเป็นกลไกของพื้นที่ที่ออกแบบไว้ชัดเจน
- **[R] เงาตัวละคร:** เงาใต้เท้าต้องมีเสมอเพื่อให้ตัวละคร "ติดพื้น" (ART §3 L21) ส่วนวิธีทำอยู่ใน `VISUAL_PROTOTYPE_PLAN.md §2.2`

### 3.4 แนวทางด้านวัฒนธรรม **[R] (รอ cultural review, DEC-053)**
- ยันต์ อักขระ และลายสักในเกม**ออกแบบขึ้นใหม่** โดยได้แรงบันดาลใจจากโครงสร้าง (ตาราง วงกลม อักขระแบบขอม) ไม่คัดลอกยันต์หรือคาถาจริงที่อ่านได้
- ไม่ใช้พระพุทธรูป พระสงฆ์ หรือสิ่งเคารพเป็นศัตรู เป้าโจมตี หรือมุกตลก
- NPC สายศาสนาหรืออาจารย์ (เช่น "หลวงพ่อ" ในภาพอ้างอิง) แสดงอย่างให้เกียรติ
- ผีและสิ่งเหนือธรรมชาติจากตำนาน (เช่น กระสือ ปอบ พราย) ใช้ในฐานะตำนาน หลีกเลี่ยงภาพสยองแบบ gore
- หัวข้อที่อ่อนไหว (เช่น กุมารทอง ซึ่งเป็นวิญญาณเด็ก) ต้องผ่าน review ก่อนผลิต

## 5. VFX Art

### 5.1 ภาษาภาพ [LOCK]
กระดาษยันต์ที่ลุกไหม้หรือแตกกระจาย · ควันหมึกและเถ้าถ่าน · วงอักขระและลายยันต์ · ไฟวิญญาณและเงาของสิ่งเหนือธรรมชาติ · คลื่นพลังจากการลงอาคม

### 5.2 โครงสร้างจังหวะ [LOCK]+[R]
ทุกสกิลมีอย่างน้อย 3 ช่วง ตามที่ Art Lock §4 กำหนด ("จังหวะเริ่มต้น จุดปะทะ และการสลายตัว") และสอดคล้องกับ lifecycle ใน COMBAT §3

| ช่วง | ผูกกับ event (COMBAT §3, §9) | หน้าที่ |
|---|---|---|
| 1. Anticipation / Cast | `CastStarted` หรือ Windup | บอกว่ากำลังจะเกิดอะไร **จากใคร** **ไปทางไหน** |
| 1b. Telegraph (สกิลพื้นที่ หรือการโจมตีของศัตรู) | Windup | แสดงรูปทรงและขนาดของพื้นที่จริงจาก server data ตั้งแต่เริ่มจนถึง resolve |
| 2. Impact | `SkillResolved`, `EntityDamaged` | จุดปะทะชัดที่สุด สั้น และมีแสงสว่าง |
| 3. Dissipation | Recovery | สลายเป็นเถ้า ควัน หรือกระดาษไหม้ ความเข้มลดลงเร็ว ห้ามค้างนานจนบังสกิลถัดไป |

**[F]** ระยะเวลาของแต่ละช่วงมาจาก game-data และ event ของ server ส่วน VFX ปรับให้พอดีกับเวลา ห้ามกำหนดเวลาของ gameplay เอง (ART §2.6 L12; COMBAT §7 L60)

### 5.3 ภาษาสีและรูปทรง **[R]**
| เจ้าของ | สีหลัก | รูปทรงหรือลวดลาย |
|---|---|---|
| ผู้เล่น (ตัวเอง) | ทอง, หมึก, เขียวหยก | วงอักขระสมบูรณ์ เส้นคม |
| ผู้เล่นอื่นหรือพันธมิตร | เหมือนข้างบน แต่ความเข้มลดลงตาม §5.4 | — |
| ศัตรู (hostile telegraph) | **แดงชาด** + ม่วงคำสาป | ขอบหยักหรือมีลายเส้นแตก และ**ต้องแยกจากของผู้เล่นได้ด้วยรูปทรงด้วย ไม่ใช่สีอย่างเดียว** (รองรับภาวะตาบอดสี) |
| Ward / cleanse | ฟ้าวิญญาณอ่อน, ขาวกระดาษ | เส้นโค้งนุ่ม |

### 5.4 ความเข้มและงบ **[R]**
- **Intensity tiers:** VFX ของตัวเอง 100%, ของพันธมิตร 50–60%, ของผู้เล่นอื่นที่ไม่เกี่ยวข้อง 25–35% (ค่า config) ส่วน **telegraph ของศัตรูต้องแสดง 100% เสมอ**
- เพดานความสว่างและความทึบ: VFX ห้ามทำให้ซิลูเอตของศัตรูอ่านไม่ออก (วิธีวัดอยู่ใน `VISUAL_PROTOTYPE_PLAN.md §5.3`)
- **Photosensitivity:** แสงวาบเต็มจอต้องไม่เกิน 3 ครั้งต่อวินาที (WCAG 2.3.1) และมีตัวเลือกปิด screen shake และ flash
- งบ particle ต่อเอฟเฟกต์และต่อฉากอยู่ใน `ASSET_PIPELINE.md §12`

### 5.5 อักขระใน VFX
**[R]** เป็น glyph ที่แต่งขึ้น (font หรือ texture ชุดเดียวที่ใช้ทั้งเกม) ไม่ใช่ข้อความภาษาไทยหรือภาษาบาลีที่อ่านเป็นคาถาจริงได้ (GDD L89)

## 6. UI Art

- **Palette [LOCK]:** พื้นดำและน้ำเงินเข้ม, กรอบทองหม่น, เน้นด้วยแดงชาด (เขียวหยกใช้เป็นสีสถานะเชิงบวก ซึ่งเป็นข้อเสนอ **[R]**)

  - health bar, target และ skill bar ต้องใช้ทั้งรูปทรงและตัวเลข ไม่ใช้สีอย่างเดียว
- **ไม่บังฉากต่อสู้ [LOCK]:**
  - HUD อยู่ที่ขอบจอ เว้นพื้นที่กลางจอ (ประมาณ 60% ของความกว้างและ 55% ของความสูง ซึ่งเป็นค่า **[R]**)
  - panel ใหญ่ (inventory, อุปกรณ์) เปิดแล้วต้องไม่บัง telegraph ที่ตัวละครยืนอยู่ เช่น เลื่อนกล้องหรือวาง panel ด้านข้าง
- **Layout จากภาพอ้างอิง [F → R]:** status ซ้ายบน, minimap และ quest ขวาบน, skill bar กลางล่าง, chat ซ้ายล่าง ใช้เป็นจุดตั้งต้นที่ดี (ยกเว้นฟีเจอร์ที่อยู่นอกขอบเขต MVP ตาม §2)
- **Font ไทย [?]:**
  - ต้องแสดงสระบน สระล่าง และวรรณยุกต์ซ้อนได้ถูกต้อง มี license ที่ bundle ในเกมได้ และอ่านได้ที่ 14px
  - หัวข้อใช้ font ตกแต่ง ส่วนเนื้อหาใช้ font อ่านง่าย
  - โลโก้ "ขมังเวท" ต้องเป็นงานออกแบบตัวอักษรเฉพาะ ไม่ใช่ font สำเร็จรูป (DEC-052)

## 9. กระบวนการอนุมัติงาน art **[R]**
1. **Concept / reference sheet** เทียบกับ bible นี้
2. **Turnaround** ตามทิศที่กำหนด + ทดสอบ silhouette
3. **Animation test** แบบหยาบใน engine (ตรวจเท้าไถล, pivot, น้ำหนัก)
4. **In-engine test** ใน benchmark scene ภายใต้แสงและหมอกจริง
5. **Sign-off** ตาม rubric ใน `VISUAL_PROTOTYPE_PLAN.md §5.1` แล้วบันทึกใน asset manifest
